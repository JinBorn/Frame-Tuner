## P1-01：刷新动画列表覆盖未保存的编辑状态

**事实与位置**

“刷新动画列表”的处理器在 `tools/animation_tuner/public/app.js:6544` 清理图片缓存后直接调用 `loadConfig()`，没有检查 `dirty` 或 `saveInFlight`。`loadConfig()` 从 `app.js:1904` 开始用服务端配置重新赋值变换、播放和框体等编辑状态。该刷新路径没有同步重置 dirty 标记与撤销栈，也没有项目切换路径中的丢弃确认。

**待复现条件**

打开已有动画，修改某帧偏移、时长或框体且不保存，点击“刷新动画列表”，检查参数、预览、未保存提示和撤销状态。

**影响**

内存中的未保存修改会被服务端旧值替换；界面仍可能提示未保存，撤销历史也可能与当前加载的数据不一致。此处不主张数据必然不可恢复，需单独验证撤销行为。

**建议与验收**

为刷新明确保存或丢弃编辑的流程，并与保存中的状态互斥。验收应覆盖：有未保存修改时不会无提示覆盖；选择保留编辑后参数不变；明确丢弃后加载服务端数据且 dirty/撤销状态一致；保存中的刷新不会交叉提交或替换状态。

## P1-02：快速切换动画时，过期图片加载可能覆盖当前选择

**事实与位置**

`tools/animation_tuner/public/app.js:1978` 的 `selectGroup()` 在 `app.js:1992` 设置全局 `currentGroup` 后，等待图片、复合图层、附件和连播图片加载，再更新下拉框、标题与画布。相关异步路径从 `app.js:1997`、`app.js:2060` 开始读写共享状态，未见选择代次校验或取消机制。`app.js:6591` 的动画选择处理器可以再次调用此函数，也未捕获该调用的异步错误。

**待复现条件**

让动画 A 的图片加载较慢，在 A 尚未加载完成时切换到较快的 B，再等待 A 完成。也应验证角色切换和搜索自动切换动画的同类场景。

**影响**

旧调用可能在新选择后覆盖图片、复合上下文、下拉值或标题，使当前编辑对象和预览内容不一致；图片加载失败也可能只产生未处理的 Promise 拒绝。

**建议与验收**

按选择代次加载并提交完整上下文，拒绝过期结果，同时显示可恢复的加载错误。验收需人为控制 A/B 的完成顺序，确认最后一次选择始终决定当前组、图片、标题、时间轴和参数面板；失败后能够重新选择或重试。

## P2-01：播放推进丢弃时间余量，预览节奏可能慢于设置

**事实与位置**

`tools/animation_tuner/public/app.js:5993` 的 `animate()` 在一轮 `requestAnimationFrame` 中最多推进一帧；满足间隔条件后使用 `lastPlay = time`，未保留本次超过帧时长的余量，也没有补偿多个已到期帧。

**待复现条件**

使用不能整除屏幕刷新周期的帧时长，例如每帧 40ms；记录若干轮循环的实际时间，并与时间轴设置比较。再增加主线程负载或使用长短不等的逐帧时长，检查误差是否累积。

**影响**

每轮刷新舍弃的时间可能累积，使预览总时长长于编辑器显示的时长，降低人工调参结果与导出或引擎运行结果的一致性。当前未进行浏览器计时测量。

**建议与验收**

使用累计播放时间或绝对时间轴计算帧位置，并明确延迟时跨帧事件和音效的处理规则。验收应覆盖固定时长、混合时长、禁用帧和短暂卡顿，量化多轮播放总时长与设置值的误差；跨帧音效不能因补偿而意外重复。

## P2-02：固定高度约束可能让短窗口中的画布与时间轴重叠或裁切

**事实与位置**

`tools/animation_tuner/public/style.css:695` 将工作区设为 `100vh`，网格行设为 `auto minmax(0, 1fr) 264px`，并隐藏溢出；`style.css:840` 为画布另设 `min-height: 300px`。工具栏、间距、内边距、时间轴和画布最小高度可能超过可用高度。`style.css:1495` 的主要响应式断点仅按窗口宽度切换布局。

**待复现条件**

在宽度大于 960px、高度约 600px 的内容视口中打开页面；另外检查工具栏换行、浏览器缩放以及长标题时的布局。

**影响**

画布可能超出分配的网格行，与时间轴重叠或被外层裁切；关键控件可能不便访问。具体显示结果仍需浏览器验证。

**建议与验收**

先确认最低支持视口，再协调画布最小高度、时间轴高度和滚动策略。验收应在确认的最小视口及常用桌面尺寸下检查：画布与时间轴不互相覆盖，保存和播放入口可达，长标题与缩放不会隐藏必要操作。

## P2-03：帧卡内部嵌套交互控件，语义与键盘行为需要修正

**事实与位置**

`tools/animation_tuner/public/app.js:4397` 将整张帧卡创建为 `button`；`app.js:4413` 的内部模板又包含时长调节按钮，并包含带 `role="button"` 和 `tabindex` 的复制、删除音效控件。这种按钮内嵌套交互内容的结构不符合 HTML 按钮内容约束。主画布在 `tools/animation_tuner/public/index.html:313`，没有可访问名称或替代说明。

**待复现条件**

仅用键盘依次聚焦帧卡、时长调节、复制和音效删除，检查 Enter/Space 的行为与焦点顺序；用浏览器可访问性树核对控件名称和层级。

**影响**

交互层级及辅助技术语义不清晰，可能造成重复激活或难以理解当前焦点用途。具体浏览器行为尚未复现，不将这些潜在表现视为既成事实。

**建议与验收**

将帧选择和附属操作作为并列的独立控件，并补充名称与选择状态。验收应确保每项操作只触发一次，键盘可达，焦点清晰，辅助技术能够识别当前帧和动作；鼠标多选及拖放也应保持可用。

## P2-04：全量并行预加载和未释放的图像引用会增加内存占用

**事实与位置**

`tools/animation_tuner/public/app.js:2090` 的 `startPreloadImages()` 对项目全部帧立即发起加载，未设置并发上限。`app.js:2123` 将加载完成的图片存入 `imageElements`。`app.js:1684` 的 `resetProjectSession()` 会清理 `imageCache`，但未清理 `imageElements`；该 Map 对图片保留强引用。失败的图片加载 Promise 也会留在 `imageCache` 中，直到外部显式清理缓存。

**待复现条件**

准备含较多大尺寸帧的两个项目，反复切换并观察内存占用和当前动画的首次加载时间；令一张图片暂时不可用，在资源恢复后再次选择该动画，检查是否能够重试。

**影响**

不需要立即展示的帧与当前动画竞争加载资源，已离开的项目图片仍可能被引用，长时间使用时增加内存压力；失败缓存可能阻止直接重试。尚未测量实际占用或性能差值。

**建议与验收**

优先加载当前动画，限制后台并发，对缓存建立容量和生命周期规则，并在失败时允许重试。验收应观察反复切换后的内存是否趋于稳定、当前动画是否优先可用，以及资源恢复后无需重开页面即可成功加载。

## P2-05：现有自测不能验证上述浏览器行为，并对正常页面改版较敏感

**事实与位置**

`package.json:13` 的 `check` 执行 Node 语法检查，`package.json:14` 的 `test` 执行 `tools/self_test.js`。自测包含有效的数据逻辑断言，同时从 `tools/self_test.js:531`、`self_test.js:612` 起也有大量 HTML、JS、CSS 源码正则匹配；其中部分断言要求固定中文文案、DOM 属性或实现片段存在。静态检索未发现 Playwright、Puppeteer、WebDriver 或 jsdom 的浏览器/DOM 测试入口。

**待复现条件**

本项是覆盖范围发现，不是需要用户操作触发的页面缺陷。可通过改变实现但保留被匹配字符串，或正常调整文案而保持行为，检查字符串断言与真实行为的对应程度。

**影响**

自测通过不能证明异步选择、保存状态、播放计时、焦点或响应式布局正确；正常文案与结构重构也可能触发与产品行为无关的失败。

**建议与验收**

保留数据纯函数与契约测试，将与实现细节耦合的断言逐步替换为实际行为检查。针对 P1 问题建立能在修复前失败、修复后通过的回归用例，并覆盖播放时长、最小视口与核心键盘路径。不要仅为改版添加“新字符串存在”的同类断言。

## 对页面改版有影响的现状与访谈问题

以下保留审查时的问题记录；用户后续已完成范围选择，最新结论以 [改版方案](redesign-plan.md) 为准。

1. **编辑器与产品入口。** 当前是共享的原生 HTML/CSS/Canvas 编辑器；无引擎 Lite 已存在，README 也已描述 Unity runtime 支持。`tools/frame_tuner_lite/server.js:503` 用字符串替换共享 HTML，`tools/frame_tuner_lite/public/lite.js:30` 将导出面板插入保存按钮前。重排页面结构会影响两个入口。是否统一入口，以及旧入口如何兼容，仍需确认。
2. **独立使用流程。** 普通页面提供项目切换和刷新，但常规素材导入主要依赖 Agent/CLI；`tools/animation_tuner/public/index.html:34` 起可见现有项目入口。是否加入用户直接新建项目、选择素材和导入的流程，会影响空状态与主导航设计。
3. **保存与反馈位置。** `index.html:279` 将保存按钮、保存状态和错误状态放在长侧栏末尾。是否需要固定可见的保存/导出区，以及保存与引擎同步是否分为两个操作，尚待确认。
4. **复杂功能层级。** 拖尾绘制、插入及多层材质参数与一般帧变换共用侧栏。是否提供独立工作模式、默认折叠高级参数，需结合主要用户及常用任务确定。
5. **视觉方向和设备范围。** 现有样式使用粗边框、硬阴影和橙绿强调色，已有深浅主题。是否保留这套风格、转为更克制的专业编辑器视觉，以及是否支持触屏/窄窗口，均为未确认选择。没有运行视觉证据，因此本记录不对现有页面的实际观感作结论。
6. **Cocos 与通用引擎边界。** UI 应展示哪些引擎能力、如何区分中立编辑数据与引擎输出、对未支持能力如何反馈，取决于尚待确认的 Cocos 3.8.8 接入契约。本次不预设具体导出格式或 runtime 集成深度。
