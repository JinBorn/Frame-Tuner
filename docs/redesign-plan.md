# Frame Tuner 通用化改版

> 2026-10-10 状态更新：Codex Pets 功能已移除，旧本地文件保留；下文涉及该功能的选择与计划保留为当时范围记录。当前支持范围见 [README](../README.md)。

状态：首期改版已实现，2026-10-06 完成 Windows 浏览器闭环与 Cocos Creator 3.8.8 独立演示构建、运行验收；Agent 范围包含 DeepSeek Harness。实际验证范围与剩余边界见 [验收记录](verification-2026-10-06.md)。

## 目标

- 改善页面外观和调参体验。
- 排查并改善现有实现的质量问题。
- 明确不绑定引擎的使用方式，优先支持 Cocos Creator 3.8.8。
- 扩展配套 skill 的 Agent 兼容性。

## 已确认的产品选择

- 主要使用者：独立开发者与技术美术。
- 视觉方向：现代深色专业工作台，突出动画画布、参数层级和可读性。
- 产品结构：通用核心加可选引擎适配器，默认项目不绑定引擎。
- 基础使用方式：网页独立覆盖新建项目、导入、调参和导出；Agent 用于批处理和自动化。
- Agent 范围：首批 Codex、Claude Code、Cursor、DeepSeek Harness，另附其他 Agent 的通用接入说明。
- Cocos Creator 3.8.8 首期交付：资源包、TypeScript 播放组件和独立演示场景，验证播放节奏、变换、逐帧音效及框体数据。
- 保留 Godot、Unity、Codex Pets 的已有能力，作为可选功能；默认不创建宠物项目、不访问 Codex 目录。
- 首期平台：Windows 与 Chrome／Edge 完整验收，核心命令保持跨平台，提供不依赖目录选择器的导出方式。macOS／Linux 未实测时明确标注。
- 更新来源：从 `JinBorn/Frame-Tuner` 检查并更新，保留用户触发的升级流程。
- Cocos 视觉：将主体、图片挂件及攻击拖尾烘焙为透明序列帧，优先保证画面一致；保留原始可编辑项目及独立的框体、音效、时序数据。
- 数据归属：工作台项目为权威来源，导出包与引擎资源为可重新生成的派生产物；首期单向导出，游戏业务逻辑与生成文件分开。

## 仓库基线

- 审查起点：`cb061e1`，工作区最初无未提交修改。
- 当前版本已有 Godot、Unity、Frame Tuner Lite 和 Codex Pets 分支，不能把通用化等同于从零增加第二个引擎。
- Lite 与完整版共享编辑器，已有独立素材导入与透明序列、Sheet + JSON 导出。
- 工作台的基础运行环境是 Node.js；Codex 不是启动服务的必要依赖。
- 只读 Cocos MCP 查询确认本机有可用的 Cocos Creator 3.8.8。当前打开的是其他游戏项目，尚未修改；验收方案使用独立演示，避免依赖该游戏业务逻辑。
- 基线 `npm run check` 与 `npm test` 在 2026-10-06 通过。下方审查记录保留当时状态；改版后的浏览器与 Cocos 运行证据另见验收记录。

## 首期实施范围

### 工作台与使用流程

- 统一主入口，默认进入不绑定引擎的项目；复用既有编辑能力。
- 网页支持新建项目、导入 PNG 序列或 PNG + JSON 图集、调参、保存和导出。
- 现代深色布局：项目与动作导航、主画布、时间轴、属性区及明确的保存状态；复杂拖尾参数按模式显示。
- 参数编辑、画布操作与时间轴保持可用，短窗口下关键操作可到达。
- 原有项目与启动方式保留兼容入口；读取旧数据时不静默改变其引擎归属。

### 稳定性与通用数据

- 修正未保存刷新、快速切组加载竞态、播放时序偏差和图片缓存问题。
- 修正无效的帧卡交互结构，增加必要的键盘可达性。
- 显式识别引擎与适配能力，未知类型不回退成 Godot；损坏的数据文件不静默变成可被覆盖的空项目。
- 通用导出包含帧时长、原点、图集裁切信息、框体、音效和版本信息；不支持的图集语义明确报错，避免静默错位。
- 分清像素坐标、引擎坐标、缩放、镜像及烘焙结果，确保特效与变换不会重复应用。

### Cocos Creator 3.8.8

- 交付资源包、TypeScript 播放组件与独立演示场景。
- 验证不等帧时长、禁用帧、循环与一次播放、结束事件、左右朝向、原点、框体查询及逐帧音效。
- 挂件和拖尾以烘焙视觉进入 Cocos；原始可编辑数据保留在工作台。
- 验收使用独立样例，不依赖或改造现有游戏的业务逻辑。
- “通用”指其他引擎可以消费公开的通用导出成果；引擎专属自动接入仅承诺已实现的适配器。

### Agent 与更新

- 共用工具命令、数据契约、机器可读结果和失败状态，支持批量导入、校验与导出。
- 提供 Codex、Claude Code、Cursor、DeepSeek Harness 的安装与调用入口，另附通用 Agent 说明。
- 若视觉烘焙需要浏览器运行环境，由工具明确管理依赖；不把调用系统目录选择器作为 Agent 导出的必要步骤。
- Codex Pets 显式启用；工作台更新与 skill 安装目标分开管理。
- 更新器从 `JinBorn/Frame-Tuner` 的 `main` 分支检查更新，保留本地修改保护和快进更新要求，不自动发布或推送本次改动。

## 验收计划

- 保持现有语法检查和有意义的数据自测通过。
- 为已识别的数据丢失、异步切换、播放时钟、错误引擎路由及图集语义增加针对性检查。
- 在 Windows 的浏览器中验证空项目、新建、导入、编辑、保存、重载和导出闭环。
- 在 Cocos Creator 3.8.8 中运行独立样例，对照工作台的帧时长、视觉、框体与事件。
- 检查生成资源不依赖本机绝对素材路径，重复导出可用，原项目保留可编辑内容。
- 验证 fork 更新来源与多 Agent 安装入口；未实际运行的客户端／系统明确区分为文档兼容或待实测。

## 后续迭代：网页工作流完善（2026-10-06）

首期实现已整理为提交 `0993742`。用户随后选择继续完善网页工作流，本轮范围为：

- 在图集导入界面选择配套音效；匹配 JSON 中的文件引用，缺文件或无法区分的重名明确报错，不静默丢失音效。
- 遇到同名动作时提供明确的替换确认，默认保留已有内容。取消后仍可修改名称或文件选择；确认替换清理依赖旧帧顺序的数据，并保留其他动作和角色／动作级配置。
- 导出从选择目录、测量、烘焙到打包和保存全程保持忙碌状态，阻止重复导出和冲突编辑；失败或取消后可重试。
- 导出标签与主要进度反馈随中英文切换，保留用户已填写的参数。
- 音效自动同步期间阻止冲突导出；同步失败保留内存中的音效和明确错误，可保存重试，也可导出包含该音效的可编辑快照。

本轮已完成。验收包括真实浏览器的音频字节／音量往返、缺文件与重名拒绝、取消／确认替换、延迟打包期间的互斥、音效同步与缓存一致性、失败解锁和语言切换。最终 67 个 JavaScript 文件语法检查与 16 组测试通过，详见 [验收记录](verification-2026-10-06.md)。
